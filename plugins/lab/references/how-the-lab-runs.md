# How the lab runs

The working agreement. The tutor presents this at the **start of Module 1**, not at
`/lab:start` — the opening introduction stays short on purpose.

## The teaching loop

Every block of the training runs the same five steps:

| | |
|---|---|
| **Frame** | why this exists — what broke in the last step |
| **Build** | you type. The tutor coaches, the facilitator floats |
| **Run** | you see the real output, or the real score |
| **Name** | *now* the concept gets its name and its limits |
| **Gate** | a checkpoint: your work is validated and saved |

Concepts arrive **after** the participant has felt the problem they solve. If something feels
frustrating right before a concept is introduced, that is the design working.

## The learning contract

**You type. The tutor coaches.**

The tutor explains, reviews, unblocks, quizzes and grades. It deliberately does **not** write
the participant's work for them — if it did, they would leave with something they cannot
maintain and no idea how it works. Stuck is not a failure state: `/lab:hint` gives a nudge
rather than a solution, and getting unstuck is the part that teaches.

## Checkpoints, and never being stranded

Each module has three or four **checkpoints**. At a checkpoint the work is validated and
committed, so it survives between sessions and across machines.

If something breaks badly, or a participant falls behind the room, `/lab:catchup`
fast-forwards them to the current checkpoint's known-good state. Nobody sits stuck watching
everyone else move on. It exists precisely so a bad `pip install` cannot cost someone a
module — using it is not cheating.

## Sessions are days apart

The four sessions are separate. Each one opens with a short resume: `/lab:start` shows what
was built last time, re-checks the environment, and verifies the work is still intact. A
participant can pick up on a different machine if they have to.

Between sessions there is one **optional** extension per module. It is never required, and
skipping it never blocks anyone.

## Two speeds

- **guided** (default) — full explanations, quizzes, worked examples.
- **fast** — terse, artifact-gated, for people who already know the basics.

Switchable at any time. If a participant is plainly ahead of the tutor, speed up.
